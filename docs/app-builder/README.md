# AI 助理应用构建

在轻舟 AI 助理中提供 REST 接口文档和需求，可生成应用 Maven 工程，编译后将 JAR 放入当前实例的 `apps`。源码和 POM 会保留，方便人工修改及继续构建。

## 环境

- 使用完整 JDK 1.8 启动轻舟。
- 启动轻舟的环境中，`PATH` 包含支持 Java 8 的 Maven，能执行 `mvn`（Windows 为 `mvn.cmd`）。首次构建需要下载 Maven 插件，或提前准备本地缓存。
- 配置好轻舟 AI 助理使用的模型服务，模型需支持工具调用。
- 产品包包含同版本的 `qingzhou-api` 源码和第一阶段生成指令，由产品构建过程提供。

## 生成应用

打开 AI 助理，提供接口文档正文或附件，说明应用标识、接口范围和需要的查询、修改等操作。例如：

> 请使用应用构建技能，根据下面的 REST 文档生成应用。应用标识为 inventory-check，本次只做库存列表和详情，按仓库筛选。请保存 Maven 工程并构建，缺少业务信息时先问我。

模型通过工具分段读取平台 API、保存 Java 源码，并执行 `mvn -B clean package`。编译失败会返回日志及错误位置，供模型修订；需要调整依赖、存在业务歧义或反复失败时，回到对话处理。

工程保存在当前实例的 `temp/app-builder/qingzhou-app-<应用标识>/`，包含 `pom.xml`、`src/main/java/` 和同版本依赖目录 `.qingzhou-repository/`。保留整个工程目录，才能在人工修改后继续使用 JDK 1.8 执行 `mvn clean package`。完整构建日志位于工程的 `build.log`。

## 加载与检查

构建成功后，工具将 `qingzhou-app-<应用标识>.jar` 放入当前实例的 `apps/`，并给出配置键和运行说明。服务地址及凭据通过当前实例的 `conf/qingzhou.properties` 配置。例如，应用标识为 `inventory-check`、代码读取的属性为 `server.address` 时，完整配置键为：

```properties
app~qingzhou-app-inventory-check.server.address=http://127.0.0.1:8080
```

配置后手动重启轻舟，在应用中心检查页面、筛选、详情和实际接口结果。工具只负责编译及放置 JAR，不自动重启，也不在构建时执行生成应用。编译成功仍需运行验收。

## 修改与续建

反馈问题时注明应用标识及页面现象，可附脱敏错误，例如：

> 继续应用构建 inventory-check。库存列表正常，但点击详情失败。页面提示如下，请读取现有工程定位并修订。

模型会续用已有工程，读取相关源码后修改。工具不覆盖 `apps` 中的同名 JAR；需先由用户备份、处理旧包，或选择新的应用标识，再继续构建和重启。生成工具也不会自动放置人工执行 Maven 得到的 JAR。

工具调用达到单轮上限时，使用“继续应用构建”并带上原应用标识接续。业务文档无法读取或不完整时，补充正文后继续。
