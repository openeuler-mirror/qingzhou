# 轻舟使用手册

配置项的含义、默认值、取值范围与安全约束见 `qingzhou.properties.readme`、`secret-key.properties.readme`、`mcp.json.readme`
；本手册只写操作步骤，不重复参数说明。

## 快速上手

1. **环境**：JDK 8+、Maven 3.8+（建议版本，构建未强制校验）。
2. **构建**：源码根目录执行 `mvn clean install -DskipTests`，产物为 `qingzhou/target/qingzhou`；对外发布加 `-Prelease`
   ，默认的开发档 zip 名带构建时间戳。
3. **初始化**：`cd qingzhou/target/qingzhou && sh bin/init.sh`，按提示设置全局密钥、管理员口令，可选 TOTP、TLS 证书、Agent
   域密钥。未初始化直接启动会因缺少必需配置退出。
4. **启动**：`sh bin/start.sh`，可追加实例名（默认 `default`）。
5. **访问**：`http://localhost:7900/web`，账号 `admin`，口令为初始化时设置；若初始化时启用了 TLS，改用 `https://`。

### 目录结构

```text
qingzhou/
├── bin/
│   ├── start.sh                  # 启动，可追加实例名
│   ├── init.sh                   # 交互式安全初始化，可追加实例名
│   ├── encrypt.sh                # 用实例全局密钥加密明文口令
│   ├── digest.sh                 # 生成管理员登录口令摘要
│   ├── token.sh                  # 生成访问系统的令牌
│   ├── qingzhou-launcher.jar     # 启动引导
│   └── win/
│       ├── start.bat
│       ├── init.bat
│       ├── token.bat
│       ├── digest.bat
│       └── encrypt.bat
├── instances/
│   └── default/                  # 一个实例，配置、应用、数据、日志相互隔离
│       ├── conf/                 # qingzhou.properties、secret-key.properties、mcp.json
│       ├── apps/                 # 轻舟应用（插件）投放目录
│       └── data/ logs/ temp/     # 运行期生成
└── lib/
    └── version<版本>.zip         # 平台 jar，首次启动若解压目录不存在则自动解压
```

- `init.sh`、`encrypt.sh` 需在可交互终端执行。`sh bin/encrypt.sh default` 读取明文口令并输出密文，可直接写入配置项。
- `lib` 下多版本并存时取版本号最大的目录；升级只需放入新的 `version*.zip` 后重启。解压后的 zip 可保留或删除。

### 多实例

`instances` 下每个子目录即一个独立实例。复制 `default` 为新目录（如 `instances/agent`）后，执行 `sh bin/init.sh agent`
完成初始化，`sh bin/start.sh agent` 启动。
同机多实例须在各自 `conf/qingzhou.properties` 中配置不同的 `qingzhou-http-server.port`。

## 远程管理

远程管理基于「注册中心 + Agent」模型，实现跨主机统一纳管与跨节点应用调用。

- **注册中心**：正常运行的轻舟实例，内置 registry 服务，接收 Agent 心跳、维护远程实例清单并在管控台呈现。
- **Agent**：被纳管主机上的另一个轻舟实例，按心跳周期自动注册，并暴露本机应用供中心跨节点调用。

### 一、准备注册中心

1. 按「快速上手」构建、初始化并启动一个实例作为注册中心。
2. 跨主机纳管须在 `conf/qingzhou.properties` 设置 `qingzhou-http-server.host=0.0.0.0`；非环回地址且未启用 TLS 时须同时设置
   `qingzhou-http-server.allow_plaintext=true`，否则启动即失败。生产环境应启用 TLS，跨主机明文监听会让口令与令牌暴露在链路上。
3. 按需调整 `qingzhou-registry.interval`、`qingzhou-registry.timeout`、`qingzhou-registry.trust_advertised_host`；反代/NAT
   下才需要开启自报地址开关，其 SSRF 风险见 `qingzhou.properties.readme` 对应条目。

### 二、部署 Agent

关键是与中心 **共享同一条域根密钥**：

1. 在被纳管主机解压同一份产品包，实例可用自带的 `default`，也可复制独立实例目录（如 `instances/agent`）。
2. 在 `instances/default/conf/secret-key.properties` 配置与中心 **完全相同** 的域根密钥（带外分发，切勿经网络传输）：
    ```properties
    agent-domain~default=<Base64 编码密钥>
    ```
   域名是中心与一组 Agent 共享的信任域标识，两端须同名同值，一个域可纳管多个实例。声明了 `qingzhou-agent.url`
   却缺少域根密钥时，实例启动即失败。
3. 在 `instances/default/conf/qingzhou.properties` 启用并指向中心：
    ```properties
    qingzhou-agent.url=https://<主中心>:7900,https://<备中心>:7900
    qingzhou-agent.interval=6
    # qingzhou-agent.advertised_host=<本机对外可达地址>
    ```
   主备优先级、注册路径拼接、`context_path` 前缀要求与接管时延见 `qingzhou.properties.readme` 的 `qingzhou-agent.url`、
   `qingzhou-agent.interval` 条目。协议须与中心一致，中心未启用 TLS 时用 `http://`；两端前缀互相独立，Agent
   自身的前缀由注册报文自动上报，供中心回连。
   多中心须配置同名同值的 `agent-domain~<域名>` 根密钥，且各自独立维护实例清单（进程内、无同步）：切换后由新中心重新分配实例
   ID，旧中心条目按其 `qingzhou-registry.timeout` 自动剔除。
4. 启动：`sh bin/start.sh agent`，Agent 即按 `interval` 周期心跳注册。

### 三、验证与使用

- Agent 日志首次注册成功会打印 `N apps registered`；续期不打印，应用数为 0 时同样打印，需结合下一步确认。
- 访问中心管控台，实例列表除本机（host 为 `localhost`，实例 ID 为 `-`）外会列出已纳管的远程实例（host/port/version），以此为准。
- 选中远程实例即可跨节点调用其应用；文件类参数由中心分片加密上传至 Agent 执行。

### 安全边界

- 域根密钥仅存于中心与 Agent 两侧的 `secret-key.properties`，属带外分发的信任根；链路报文用域密钥加每实例密钥加密，同域其他节点无法冒名续期或解密。
- 启用 `allow_ssl_trust_all` 或 `trust_advertised_host` 前须阅读 `qingzhou.properties.readme` 对应条目的风险说明。

## 接口与集成

默认监听 7900，接口与认证方式如下：

| 用途           | 方法与路径                                             | 认证                   |
|----------------|--------------------------------------------------------|------------------------|
| 管控台页面     | `/web`                                                 | 静态资源免认证         |
| 管控台数据接口 | `/registry/app/*`、`/registry/instance`                | 登录态 / Bearer 令牌   |
| REST 集成      | `/registry/invoke/<实例>/<应用>/<模型>/<操作>[/<id>]`  | 登录态 / Bearer 令牌   |
| MCP            | `/ai/mcp`                                              | 登录态 / Bearer 令牌   |
| 监控指标       | `/monitor/metrics`                                     | 登录态 / Bearer 令牌   |
| 登录与 OAuth2  | `/auth/*`、`/oauth2/*`                                 | 免认证（登录入口）     |
| Agent 链路     | `/registry/register`、`/agent/invoke`、`/agent/upload` | 免登录，域密钥加密保护 |

## 参数配置

配置文件位于 `产品包/instances/<实例>/conf/qingzhou.properties`，修改后重启实例生效。全部配置项说明见
`qingzhou.properties.readme`，密钥条目见 `secret-key.properties.readme`，MCP 接入示例见 `mcp.json.readme`。

## 前后端分离

前端静态资源位于 `modules/qingzhou-web/src/main/resources/webapp`，可单独部署到 Nginx；后端接口按下列前缀反向代理：

```nginx
server {
    listen 8000;

    location /web {
        alias <前端资源目录>;
        index index.html;
        try_files $uri $uri/ /web/index.html;
    }

    location ^~ /registry/ { proxy_pass http://localhost:7900/registry/; }
    location ^~ /ai/       { proxy_pass http://localhost:7900/ai/; }
    location ^~ /auth/     { proxy_pass http://localhost:7900/auth/; }
    location ^~ /oauth2/   { proxy_pass http://localhost:7900/oauth2/; }
    # 需要外部抓取监控指标时再开启
    # location ^~ /monitor/ { proxy_pass http://localhost:7900/monitor/; }
}
```

启动 Nginx 后访问 `http://localhost:8000/web`。

## 监控指标抓取

`/monitor/metrics` 需登录态，与管控台接口共用令牌（Cookie 或 `Authorization: Bearer`）。外部探针须使用长期令牌：

```sh
sh bin/token.sh <实例>   # 交互输入账号口令，选择角色与有效天数（默认 30 天，最长 365 天）
```

令牌中的角色须与应用 `@App.roles` 匹配，否则该应用指标不会出现。外部抓取还需放开上方 Nginx 配置中的 `/monitor/` 反代。

```yaml
scrape_configs:
  - job_name: qingzhou
    metrics_path: /monitor/metrics
    authorization:
      type: Bearer
      credentials: <bin/token.sh 生成的令牌>
    static_configs:
      - targets: ['<host>:7900']
```

## 常见问题

- 启动即退出并提示 `xxx is missing in ..., run bin/init.sh to initialize`：未完成安全初始化，执行 `sh bin/init.sh` 后重启。
- 提示 `!!! WARNING: no interactive terminal`：口令输入不隐藏、可能回显或被记录，`init.sh`、`encrypt.sh` 应在可交互终端中执行。
- 解压 `version*.zip` 失败：按日志提示手动解压到 `lib/version<版本>`，或删除该目录后重启触发自动解压。
- 远程实例不出现：确认中心已按「准备注册中心」设好监听地址与明文/TLS 前置条件、端口放通、`qingzhou-agent.url`
  可达且协议与中心一致、两端域密钥同名同值。
- 启用 TLS 后浏览器或 Agent 报证书错误：为自签证书补充信任，或在受控内网设置
  `qingzhou-http-client.allow_ssl_trust_all=true`（风险见 `qingzhou.properties.readme`）。
