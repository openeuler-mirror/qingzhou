# 轻舟应用开发指南

## 概述

轻舟对业务系统的管控通过调度对应的「轻舟应用」完成。应用是基于轻舟 API（`qingzhou-api`）开发的普通 Java jar，由平台转换为
OSGi bundle 运行；接口、UI 元数据与集成方式均由 API 声明，应用无需编写前端与 Controller。

| 元素   | 实现方式                      | 管控台呈现      |
|------|---------------------------|------------|
| 应用入口 | 实现 `QingzhouApp` + `@App` | 应用卡片       |
| 业务模块 | 继承 `ModelBase` + `@Model` | 功能菜单 / 页面  |
| 模块字段 | public 属性 + `@ModelField` | 表单字段 / 列表列 |
| 模块操作 | 能力接口或 `@ModelAction` 方法   | REST 接口 / 按钮 |

## 快速开始

应用是与轻舟解耦的独立 Maven 工程，工程名、坐标与包名按企业内部规范自定，不必放进轻舟源码目录。参考示例：
`apps/qingzhou-app-demo`（位于轻舟源码，覆盖全部注解与能力接口）。

### 1. 引入依赖

`qingzhou-api` 由平台提供，以 `provided` 引入；产品包内对应 jar 位于 `lib/version/modules`，可发布到企业私服或装入本地仓库。

```xml
<dependency>
    <groupId>qingzhou</groupId>
    <artifactId>qingzhou-api</artifactId>
    <version>${qingzhou.version}</version>
    <scope>provided</scope>
</dependency>
```

### 2. 编写应用

- 全应用只允许一个 `@App` 类，实现 `QingzhouApp`；`start()` 抛异常即应用启动失败。用 `@Menu` 配置菜单。
- 模块继承 `ModelBase` 并加 `@Model`，按需实现能力接口（见「能力接口」），实现即生成对应动作与按钮。
- 业务数据用 public 字段 + `@ModelField`，框架按 public 字段读写，字段名默认即数据 key。
- 自定义动作用 public 方法 + `@ModelAction`，方法参数有且只能有一个 `Request`。

```java
@Menu(name = {"基础功能", "en:Basic"}, code = "basic", icon = "User", order = 1)
@App(roles = "admin", icon = "DataBoard",
        name = {"示例应用", "en:Demo Application"},
        info = {"用于演示轻舟应用开发。", "en:Demos Qingzhou app development."})
public class DemoApp implements QingzhouApp {
    @Override
    public void start(AppContext context) {
        context.getService(Logger.class).info("demo app started");
    }
}

@Model(code = "student", menu = "basic", name = {"学生", "en:Student"})
public class Student extends ModelBase implements Page, Show, Add, Update, Delete {
    @ModelField(id = true, readonly = true, list = true, name = {"ID", "en:ID"})
    public String id;

    @ModelField(name = {"姓名", "en:Name"}, required = true, list = true, search = true)
    public String name;

    @ModelAction(code = "graduate", icon = "Check", list = true,
            name = {"毕业", "en:Graduate"}, confirm = {"确认该学生毕业？", "en:Graduate this student?"})
    public void graduate(Request request) {
        // request.getId() 即被操作记录 ID
    }
}
```

### 3. 构建与部署

1. 执行 `mvn clean package` 打包。
2. 将 jar 放入 `${轻舟产品包}/instances/<实例>/apps`。
3. 重启轻舟，管控台可见开发的应用。

## API 与注解

签名、属性、默认值与校验规则一律以 `qingzhou-api` 源码 javadoc 为准，此处只列职责。

### 核心类型

| 类型                     | 职责                                                                 |
|------------------------|--------------------------------------------------------------------|
| `QingzhouApp`          | 应用入口，`start()` 必须实现，`stop()` 可选                                    |
| `ModelBase`            | 模块基类：提供 `AppContext`、当前请求、模块启停回调；模块是单例，动作并发进入，状态须自行保证线程安全           |
| `AppContext`           | 应用配置、实例目录、平台共享服务（`getService`）、应用级过滤器（`addActionFilter`）             |
| `Request` / `Response` | 请求参数与链式响应；动作既未写 `data` 也未写 `msg` 时框架返回 404，避免"静默成功"                 |
| `ActionFilter`         | 应用级过滤器，在 `start()` 中注册，位于框架内置校验之后、业务动作之前；不调用 `chain.doFilter()` 即中断 |

### 元数据注解

| 注解             | 目标     | 用途                                                  |
|----------------|--------|-----------------------------------------------------|
| `@App`         | 类      | 应用元数据；`roles` 未声明则所有请求 403                            |
| `@Menu`        | 类（可重复） | 功能菜单，支持多级（`parent`）                                  |
| `@Model`       | 类      | 模块元数据，`code` 缺省为类简名                                 |
| `@ModelField`  | 字段     | 表单 / 列表 / 搜索 / 监视字段，`code` 是三方对齐的唯一键               |
| `@ModelAction` | 方法 / 类 | 方法上定义动作；类上只覆盖内置动作的展示与权限元数据，不改执行逻辑                   |
| `@I18n`        | 类（可重复） | 表单分组与图表标题的文案，供字段 `group` / `chart_title` 引用      |

- 注解 `@Retention` 均为 CLASS，构建期提取；`name`/`info` 为国际化数组，元素格式 `"文案"`（默认简体中文）、`"en:Text"`、`"zh_Hant:文案"`。
- `icon` 使用 **Element Plus Icons** 官方图标名，参考 https://element-plus.org/zh-CN/component/icon.html#icon-collection。
- `display` 只控制界面显隐与 `required` 是否生效，不构成权限；语法见 `@ModelField#display`。

### 能力接口

| 接口                      | 动作                     | 说明                                |
|-------------------------|------------------------|-----------------------------------|
| `Page`                  | `page`                 | 列表与总数，每行 `String[]` 须与 `listFields` 顺序严格一致 |
| `Show`                  | `show`                 | 记录详情                              |
| `Add` / `Update`        | `add` / `update`       | 新增 / 更新；`data` 只含本次提交且对应 `add`/`update=true` 的字段，`update` 剔除 `id` |
| `Delete`                | `delete`               | 批量时调用 `delete(List)`，默认逐条委托，可覆写为整批处理 |
| `Monitor`               | `monitor`              | 监视数据                              |
| `Download`              | `file`、`download`      | 返回文件或父目录（列目录，不递归）                 |
| `Namespace`             | `namespace`、`current`  | 命名空间切换                            |

- `page` 的 `query` 只包含 `search=true` 且非空的条件；`pageNum` 默认 1，`pageSize` 默认 10、上限 100，`total` 返回 -1 表示不分页。
- 实现能力接口即生成内置动作（含按钮、图标、确认文案）；同 code 的 `@ModelAction` 只换元数据，自定义下载入口应实现 `Download`。

## 运行期行为

### REST 入口

模块动作无需额外代码即自动获得 HTTP 接入能力。通过 `POST /registry/invoke/{instance}/{app}/{model}/{action}/{id}` 调用，
参数来自 URL query 与 POST body（表单或 JSON），响应体为 `{"success":bool, "data":..., "msg":..., "msgLevel":...}`；
权限拒绝返回 403，动作未执行且无返回内容返回 404。同一套动作同时被管控台、AI 工具与监控采集复用，
应用侧无需为不同调用方重复实现。

### 权限

标注了 `roles` 的 `@App` / `@Model` / `@ModelAction` 自动获得角色鉴权能力：三级逐级继承，**未声明即拒绝（fail-closed）**，
应用级至少要声明一次。通过 REST 入口与 AI 工具调用生效，两者共用同一判定；监控数据经 `/monitor/metrics` 导出，
只要求登录态、不按应用角色判定，监视字段不要放按角色隔离的敏感信息。`display` 只影响按钮显隐，不承担鉴权，
敏感操作必须同时声明 `roles`。

### 文件上传

标注了 `@ModelField(input_type = InputType.file)` 的字段自动获得 multipart 上传能力：请求按 multipart 解析，字段值是服务端临时路径
（`<实例>/temp/qingzhou-upload` 下，框架会自主清理）。应用通过 `Request.getParameters()` 取值，自行搬移需长期保留的文件，
并校验文件名与路径合法性（含目录穿越、符号链接）。

### 监控数据

模型实现 `Monitor`、字段标注了 `@ModelField(field_type = FieldType.monitor)` 后自动获得监视数据出口：管控台按 `monitor` 动作拉取展示，
`/monitor/metrics` 抓取时导出为 `qingzhou_app_monitor_value`（label 带 `app` / `model` / `field`）。应用通过 `monitor(String id)`
返回以字段 `code` 为 key 的 Map；只有能解析为数值的字段出样本，其余仅作页面展示，采集不到时省略该 key，不得填 `-1` 等哨兵值。
`numeric = true` 只决定图表渲染，不影响指标导出。

## 主动发现

应用与目标软件通常独立部署，配置 `Qingzhou-Detection-*` 后由引擎每 5 秒（系统属性 `qingzhou.detect.interval`，单位秒）探测：
命中的安装目录各启动一个 bundle 实例（多个目录时实例 code 追加 `[序号]`，`AppContext.getDetectedPath()` 返回各自目录），
全部未命中即停止该 bundle。在 `META-INF/MANIFEST.MF` 中声明，经 `maven-jar-plugin` 的 `manifestEntries` 注入：

```xml
<plugin>
    <artifactId>maven-jar-plugin</artifactId>
    <configuration>
        <archive>
            <manifestEntries>
                <Qingzhou-Detection-Enabled>true</Qingzhou-Detection-Enabled>
                <Qingzhou-Detection-Feature-Files>bin/startup.sh,conf/config.xml</Qingzhou-Detection-Feature-Files>
                <Qingzhou-Detection-Env-Vars>DEMO_HOME</Qingzhou-Detection-Env-Vars>
                <Qingzhou-Detection-Scan-Roots>user.home,/usr/local,/opt</Qingzhou-Detection-Scan-Roots>
                <Qingzhou-Detection-Process-Names>com.example.demo.Server,demo.jar</Qingzhou-Detection-Process-Names>
                <Qingzhou-Detection-Process-Home-Regex>-Ddemo\.home=(\S+)</Qingzhou-Detection-Process-Home-Regex>
            </manifestEntries>
        </archive>
    </configuration>
</plugin>
```

探测顺序为 `Env-Vars` → `Scan-Roots` → `Process-Names`，每个候选目录按 `Feature-Files` 校验，命中任一即收集。

| 参数                                      | 必填 | 默认值     | 说明                                                                                 |
|-----------------------------------------|----|---------|------------------------------------------------------------------------------------|
| `Qingzhou-Detection-Enabled`            | 否  | `false` | 是否启用主动发现，未启用时后续参数全部无效                                                              |
| `Qingzhou-Detection-Feature-Files`      | 是  | -       | 特征文件列表，逗号分隔，相对候选安装目录的路径；命中任一即收集该目录，为空则永不命中                                         |
| `Qingzhou-Detection-Env-Vars`           | 否  | -       | 环境变量名列表，变量值直接作为安装目录，如 `JAVA_HOME`                                                   |
| `Qingzhou-Detection-Scan-Roots`         | 否  | -       | 扫描根路径列表，仅扫描根目录及其一级子目录；整项等于 `user.home` 时替换为当前用户主目录                                  |
| `Qingzhou-Detection-Process-Names`      | 否  | -       | 命令行关键字列表，小写匹配，命中后取关键字之前的命令行片段作为目录；仅在前两种策略均未命中时启用                                    |
| `Qingzhou-Detection-Process-Home-Regex` | 否  | -       | 从命中进程命令行提取安装目录的正则，须含一个捕获组，优先于关键字前缀；JVM 进程用它从 `-Dxxx.home=` 定位，如 Tomcat 配 `-Dcatalina\.home=(\S+)` |

`AppContext.getDetectedPath()` 返回 `null` 时保持等待，不要抛异常终止应用，引擎会在下次探测命中后重新启动。

## AI 辅助开发

轻舟提供 `qingzhou-app-builder` 技能包，可根据目标系统已有的 REST 接口文档（OpenAPI / Swagger / 普通接口文档）辅助生成轻舟应用，
产物是标准的轻舟应用 jar。技能包随源码提供、不随产品包分发，具体安装与使用方式见 `tools/qingzhou-app-builder-skill/USAGE.md`。
