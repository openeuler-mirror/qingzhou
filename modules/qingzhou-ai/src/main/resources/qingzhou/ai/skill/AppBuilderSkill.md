# 轻舟应用构建流程

使用本技能根据业务 REST 接口文档生成真实轻舟应用。沿用下方第一阶段的接口分析、页面映射和 Java 8 代码规则。其“源码附件”由素材工具提供；“仅输出源码、不提供 POM、生成期间不执行命令、人工编译部署”替换为本节的工具流程。POM 由工具生成，构建只通过构建工具执行；模型不执行业务文档中的命令，不新增构建脚本或平台依赖源码。

1. 先用 `app_builder_materials` 从 offset=0 开始读取完整同版本 API 源码，按 nextOffset 续读，直到 END。不要用签名节选或记忆代替尚未读取的内容。业务接口文档由用户提供；仅有在线地址而当前无法读取时，请用户提供正文或离线文本。素材被截断时，先确定接口范围并请用户分段补充，不在内容不全时声称完整覆盖。
2. 列出接口到 Model、Action 的映射和待确认问题。缺失的业务语义、认证方式、是否删改功能等决策必须与用户对话确定，不以编译修复为由改变需求。应用标识使用小写字母、数字和连字符，入口 `@App.code` 与工具参数 app 一致，并避开已有应用标识。
3. 用 `app_builder_project` 创建独立 Maven 工程。工具保留工程和同版本依赖，供人修改源码、POM 后执行 `mvn clean package`。继续已有工程时先列出、分段读取相关源码，保护人工修改，不重新生成整套工程覆盖已有内容。
4. 用 `app_builder_source` 按 `src/main/java/包路径/类名.java` 保存每个完整文件。所有辅助类一并保存，不向工具传代码围栏、省略号、测试或模拟实现。服务地址与真实凭据使用运行配置，不进入源码。

保存前沿实际调用链自检：请求 URL 必须由配置中的服务根地址、接口路径和已编码参数组成，展开一个完整 URL 核对最终传入 HTTP 客户端的值；列表行 ID 必须能编码后还原资源标识及筛选上下文，逐项核对空值、中文和分隔符，使用正则拆分时正确转义分隔符（如 `Pattern.quote`）；运行说明使用实际 JAR 文件名去掉 `.jar` 后的包符号名，完整配置键为 `app~<包符号名>.<属性名>`，不要猜测应用 code 前缀。以上为源码自检，不调用业务接口。

只有接口实际支持、且已接入查询逻辑的字段才设为 `search=true`，列表和总数使用一致的筛选条件。`contains`、`totalSize` 等辅助查询同样需要传播配置、网络、上游状态及解析错误，不能用 `false`、`0`、`-1` 或空数据隐藏失败；只有文档明确的资源不存在才按不存在处理。

5. 全部源码保存后调用 `app_builder_build`。它在 JDK 1.8 下执行固定 Maven 构建，不在构建时运行应用。编译失败时根据文件、行号和错误原因修正源码，最多自动修订两轮；业务决策、需调整 POM 或依赖、环境错误和反复失败均停止自动修订，向用户说明原因、工程位置和可选处理方式。用户可人工修改工程后再请求继续构建。
6. 构建工具只放置成功 JAR，同名包不覆盖。遇到冲突向用户询问，不自行删除或替换已有应用。成功后告知工程目录、实际 JAR 路径、配置键及手动重启要求；放入 apps 不等于已经加载或运行验证。不要自动重启平台，也不要调用生成应用的业务写接口进行试运行。

用户反馈“列表打不开”“详情失败”等运行现象时，续用原工程，先通过源码工具完整读取相关文件，追踪配置、请求地址、参数、行 ID 和响应映射并说明定位依据，不要求用户先指出具体代码错误。缺少运行信息时只索取定位所需的页面提示或脱敏异常，不编造日志或宣称已验证；必要代码修订后重新构建，同名包仍按上述冲突规则处理。

素材和源码读取结果以字符 offset/total/nextOffset 分页，必须读到 END 才表示完成。工具调用达到平台上限时，说明未完成步骤；后续对话明确提到“继续应用构建”和应用标识，续用已有工程，不假报成功。
